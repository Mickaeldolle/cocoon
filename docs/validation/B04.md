# Validation B04 — provider LLM local

Date : 2026-09-22

## Tranche livrée

- Ajout de `app/modules/assistant/providers.py`.
- Définition du contrat `LLMProvider`.
- Le contrat expose `chat`, `stream_chat` et `generate_structured`.
- Implémentation `OpenAICompatibleProvider` pour Ollama ou un serveur compatible privé.
- Déplacement de l’appel HTTP hors de `assistant/service.py`.
- Ajout de `assistant/tools.py` avec un registre interne en lecture seule : tâches, agenda et mémoires actives.
- Chaque lecture vérifie l’owner en SQL et borne le nombre de résultats ; les outils inconnus sont refusés.
- Les paramètres d’outils hors schéma sont refusés et le test de registre vérifie une séquence A/B/A sans fuite entre comptes.
- Le registre n’exécute ni shell, ni sous-agent, ni appel réseau arbitraire.
- Le chat utilise désormais les lectures bornées tâches et agenda du registre dans son contexte personnel ; aucune confirmation ni écriture n’est déléguée au provider.
- Chaque construction de contexte applique un budget borné d’appels et de durée aux outils internes.
- Le budget détecte aussi les appels identiques répétés et arrête une boucle A/B/A avec une erreur `429` ; les outils restent strictement en lecture.
- Credentials, URL et modèle restent exclusivement dans la configuration FastAPI.
- Le mobile reçoit uniquement `runtime: local` et ne connaît pas le provider.
- Hermes n’est pas intégré au runtime MVP.
- Les opérations structurées distinguent maintenant l’indisponibilité du provider (fallback `rules`) d’une réponse invalide (erreur `502`) ; le chat personnel ne masque pas une indisponibilité par un fallback silencieux.
- La conversation expose désormais `/api/assistant/chat/stream` : accusé `started`, fragments `delta`, résultat `complete` avec persistance du message et propositions, ou erreur structurée ; le mobile consomme ce flux et permet d’arrêter la requête.
- Le générateur SSE surveille `Request.is_disconnected()` et transmet la coupure à `cancel_event`; le provider coopératif cesse alors de lire les deltas et le message assistant n’est pas persisté après une coupure avant la fin.

## Limites restantes

- La latence jusqu’au premier token et la tenue après redémarrage restent à mesurer dans l’environnement cible ; le script local rejoué le 22/09/2026 a répondu `OK` en 444 ms, 410 ms et 3 399 ms, ce qui confirme une variation sensible selon l’état du modèle mais ne remplace pas une mesure dédiée du premier token.
- L’annulation mobile interrompt la lecture HTTP côté client ; la détection d’une déconnexion réseau par le serveur et l’annulation fine d’une génération Ollama restent à qualifier sur appareil.
- Le registre d’outils provider reste en lecture seule ; les propositions structurées `grocery_item` et `training` passent désormais par l’exécuteur B02 après confirmation explicite. L’annulation reste coopérative et doit encore être reliée à une route de génération réelle.
- Les écritures `grocery_item` et `training` sont couvertes par un test : aucune ressource n’existe avant confirmation, puis l’exécuteur B02 crée uniquement la ressource confirmée.
