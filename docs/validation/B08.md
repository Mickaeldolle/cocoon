# Validation B08 — qualification bêta

Date : 2026-09-22

## Tranche livrée

- Compose sépare API, PostgreSQL, Redis, Caddy, le worker de captures et le worker de rappels ; PostgreSQL, Redis et l’API ne sont pas publiés directement.
- Le service Compose `migrate` applique `alembic upgrade head` une seule fois avant le démarrage de l’API et des workers.
- `/health` reste une sonde de vie ; `/health/ready` vérifie la disponibilité de la base primaire et renvoie 503 si elle n’est pas prête.
- Chaque réponse HTTP expose un `X-Request-ID` corrélable ; le logger HTTP conserve uniquement méthode, chemin, statut, durée et identifiant, jamais le corps ou les tokens.
- Un identifiant client invalide est remplacé par un UUID généré par le serveur ; les exceptions non gérées sont également corrélées sans journaliser leur contenu de requête.
- Le worker de rappels est un service séparé et attend la réussite du service de migration avant son démarrage.
- Les commandes locales de qualification restent documentées dans `TASKS.md` et `docs/deployment.md`.

## Limites restantes

- Aucun déploiement Docker, redémarrage, sauvegarde/restauration ou test de concurrence réseau n’a été exécuté ; une migration Alembic réelle a toutefois été rejouée avec succès sur PostgreSQL 14.24 local jusqu’à `20260922_29`.
- Les métriques sont instrumentées et protégées ; un scraper/une alerte réels restent à brancher dans l’environnement bêta.
- `age` n’est pas installé ici et aucun PostgreSQL bêta dédié n’est disponible ; aucune restauration réelle n’est revendiquée.
- Aucun build Android/iOS réel n’a été installé et aucun fournisseur STT/Expo n’a été sollicité ; Ollama local a toutefois été appelé ponctuellement via l’adaptateur FastAPI avec `gemma4:e4b`, en chat et en streaming.
- Le lint mobile conserve les erreurs préexistantes de `use-secret-gesture.ts`, laissé volontairement inchangé pour préserver la messagerie secrète.
- Le MVP ne doit pas encore être présenté comme une bêta validée sur appareil ou en production.
